# ADR-0018 evidence: chunk put and flush cost on the reference machine (2026-10-15)

**Machine:** the reference machine (Windows 10, Ryzen 5600X, solid-state drive), release build.
**Command:** `journal-ack-bench`, from branch `p3/a1-chunk-durability`. The nightly
`ack-latency` job produces the Linux and macOS rows on CI runners.

| Series (4 KiB chunks) | n | p50 | p95 | p99 | p99.9 |
|---|---|---|---|---|---|
| `chunk-put`: strict, both files flushed before return | 1,000 | 2.41 ms | 2.80 ms | 3.11 ms | 11.3 ms |
| `chunk-put-balanced`: handed to the OS, temporary and rename **(shipped)** | 32,000 | 1.64 ms | 1.82 ms | 2.10 ms | 12.4 ms |
| `chunk-put-balanced`: created in place under the final name (measured, rejected) | 32,000 | 0.89 ms | 2.56 ms | 7.54 ms | 13.7 ms |
| `group-flush-chunks`: one flush covering 64 records, each with its own new chunk (128 files, then the segment) | 500 | 50.9 ms | 60.0 ms | 65.5 ms | 132 ms |
| `balanced`: journal append, for reference | 20,000 | 4.2 µs | 5.4 µs | 29.2 µs | 67.6 µs |

**What this shows.**
- **Removing the flush helps, but not enough.**
  - Removing the flush from the put path cuts p99 from 3.1 ms to 2.1 ms on this machine.
  - The rest is file creation, two files per chunk, and Windows' file-system filters.
  - ADR-0018's target of p99 ≤ 0.5 ms is **not met** on this platform.
- **Creating in place trades the wrong way.** It halves p50 but triples p99. The overhead SLO is
  judged at p95 and p99, so the rename stays.
- **The flush cost lands on the power-loss window, not on requests.**
  - Each file flush costs about 0.4 ms here. A window holding 64 new chunks therefore takes
    about 51 ms to flush.
  - Real traffic adds a few chunks per request, not 64 per window.
  - With the flush on its own thread (the WP3.3 state actor), this cost widens the effective
    window W instead of delaying acknowledgements.
- **This is ADR-0018 Decision 4's trigger.**
  - One key file per chunk is now a measured cost on the hot path.
  - The follow-up is a per-pocket keystore log, which halves the file count. It changes shred
    semantics (ADR-0007), so it needs its own ADR and a maintainer decision.
