# ADR-0014 evidence: the WP3.0c splice spike (2026-10-15)

**Source:** branch `spike/wp3.0c-splice`, commit `ccbe18a`, `spikes/splice/RESULTS.md`. The code
is throwaway and lives outside the workspace; this page records what it showed.

**Environment:** the reference machine (Windows 10, Ryzen 5600X), release build, single thread.
Transcripts are synthetic, shaped by the Claude Code capture CAP-5/6/7:
- 3 system blocks, the attribution block first;
- 29 tools;
- signed thinking blocks;
- a `cache_control` breakpoint that moves every turn;
- mid-conversation `role: "system"` messages.

No real-client transcript was used.

| Criterion | Result |
|---|---|
| Value-prefix stability: 200 seeds × 50 turns with secret splice, tag strip and append-only injection. Each turn the client re-serializes its whole history in a random style | 10,000 / 10,000 turns stable; 277,127 kernel edits; 0 secret leaks |
| Design negatives | Without per-chunk pinning, stability breaks. With `cache_control` in chunk digests, it breaks |
| Identity (transforms off) | 5,000 / 5,000 requests byte-identical |
| Role violations (signed, `system[0]`, non-secret edits in system entries and system messages, opaque, provider-produced, tag strip or append outside the newest human turn) | 8 / 8 refused |
| Parser violations (duplicate keys including after escape decoding, lone surrogates, depth 129, trailing data, leading zero, raw control character) | 8 / 8 rejected |
| Differential against serde_json on 20,000 random and mutated documents | 0 decoded-value mismatches, 0 unexplained disagreements. 8 numbers beyond f64 range were accepted only by the tape (grammar-valid) |

| Stage at 1.70 MB (p50 / p95) | Measured | Plan v2 §2.4 budget |
|---|---|---|
| Tape parse | 1.70 / 1.87 ms | decode 2 ms |
| Chunk value digests (SipHash stand-in) | 2.08 / 2.21 ms | digests 2 ms, **over by 4%** |
| Full path with history pinned | 5.93 / 6.21 ms | decode + digests + splice 6 ms |

**Digest fix, within its own stage:**
- a raw-bytes fast path, so canonical hashing runs only for chunks whose bytes changed;
- SHA-256 on aws-lc measured in place of the stand-in.

**Not shown:**
- the OpenAI Responses dialect;

- a real detector;
- concurrency;
- Linux and macOS;
- real-client transcripts.
