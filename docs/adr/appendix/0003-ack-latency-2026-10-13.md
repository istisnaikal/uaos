## Verdict

- **H1 holds on all three OSes.** Handing a critical record to the OS before acknowledging it
  costs p99 7–29 µs, far inside the 1 ms target.
- **W = 50 ms stands.** The slowest group flush observed (p99.9) is 29.5 ms (Windows runner),
  and macOS with `F_FULLFSYNC` is 13.5 ms. The default window covers the flush it schedules.
- **Strict mode is viable but costly on macOS** (p99 2.0 ms, p99.9 14.8 ms). It stays opt-in.
- **The chunk store does not fit the overhead budget.** `ChunkStore::put` flushes each chunk to
  stable storage before acknowledging it: `sync_data` plus a directory sync, for both the data
  file and the wrapped key. On macOS a **single** new chunk costs 28.5 ms at p99, which is more
  than the whole 25 ms p95 local-overhead SLO. This is phase debt PD-18. ADR-0018, chunks
  joining the journal's durability classes, is therefore a **precondition of P3**, not an
  optimization.
- Tails above 10 ms appear on every runner, including in balanced appends (max 20–22 ms). They
  coincide with window-triggered flushes and shared-disk contention. The P3 overhead bench
  measures them against the end-to-end budget, not in isolation.
